## 三、W3：P4 构建面板异步化

**现状锚点**：
- `csharp_script.cpp:2230` — `OS::execute(dotnet, ...)` 同步阻塞主线程
- `mono_build_panel.cpp` — UI 与输出路由（`append_output` / `set_status`）已就绪，只差执行模型改造
- spec 明确遗留项：「异步化涉及构建线程与 Mono domain 交互，另立项」（`mono_editor_spec.md` §6.3）——即本项

### 任务分解

| 天 | 任务 |
|----|------|
| D1 | **方案 spike（0.5 天）**：确认 Godot 4.7 `OS::create_process` 输出管道支持（`read_output` + 轮询 API 可用性）。路径 A（优先）：`create_process` + stdout 重定向 + 主线程 `frame()` 轮询增量读 → 流式输出 + 可取消（kill PID），与现有 `build_pending` 帧驱动模式天然一致；路径 B（回退）：`Thread` + `OS::execute` 一次性捕获 + `call_deferred` 回主线程 |
| D2-D3 | **核心改造**（`csharp_script.cpp` + `mono_build_panel.cpp`）：① 新增 `BuildState { IDLE, BUILDING, RELOADING }` 状态机，BUILDING 期间重复 `request_build()` 合并排队（复用 build_pending 去抖）；② **硬约束：Mono 重载必须回主线程**——`open_versioned_assembly` / `refresh_global_classes` / `reload_all_pending_scripts` 涉及 GC bridge 全局 domain 指针与 CSharpInstance 裸 `MonoObject*`（P5 子 domain 评估已确认此耦合），全部留在主线程；③ 面板：构建中禁用 Build 按钮 + 状态文案 + 新增 Cancel 按钮（路径 A 专属）；④ 崩溃安全：编辑器退出时若 BUILDING → 终止子进程并等待句柄回收，防 UAF |
| D4 | **验证**：构建大型工程期间编辑器视口/面板操作零卡顿；连按 Ctrl+S 多次只触发一次构建；失败红色高亮不回归；WASM 构建（TOOLS 裁剪路径）无符号泄漏（`check_wasm_leak` 通过） |

**明确不做（列为后续）**：诊断解析可点击跳转（spec P4 v2 项）、构建缓存加速。

**里程碑 M-W3**：构建期间主线程零阻塞（编辑器帧率不降）；重复构建请求合并率 100%；现有回归全 PASS。
