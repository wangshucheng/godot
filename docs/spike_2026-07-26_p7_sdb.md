## 核查项 1：桌面 Mono 静态库是否启用 `--enable-debug` / `--with-monodbg`

### 核查方法
1. 用 Glob 定位桌面 Mono 静态库（排除 `mono/libs/web/wasm/`）
2. 检查 Mono SDK 头文件是否声明 sdb API（`MONO_API` 导出符号）
3. 用运行时日志 `csharp_test/p7_verify.log` 验证 `--debugger-agent=` 选项是否被 Mono 接受
4. 因环境无 shell 工具，无法直接对 `.lib` 运行 `dumpbin /symbols` / `nm`；改用「头文件 API 声明 + 运行时选项接受行为」作为间接证明

### 发现
- **桌面静态库位置**：`mono\libs\windows\x64\` 下有 3 个文件
  - `libmono-static-sgen.lib`（~29MB，**完整 Mono SGen 运行时静态库**，被 Windows editor 构建链接）
  - `mono-2.0-sgen.lib`（~274KB，仅为 DLL 导入库）
  - `MonoPosixHelper.lib`
- **SCsub 构建配置**（`modules/mono/SCsub:439-461`）：msvc 路径下显式链接 `libmono-static-sgen.lib`，注释明确「contains the full Mono SGen runtime」
- **SDK 头文件**：`mono\include\mono-2.0\mono\metadata\mono-debug.h` 存在，声明了 sdb 公共 API（均带 `MONO_API` 导出标记）：
  - `mono_debug_init(MonoDebugFormat)`（行 157）
  - `mono_debugger_method_has_breakpoint`（行 224）
  - `mono_debugger_insert_breakpoint`（行 225）
  - `mono_set_is_debugger_attached` / `mono_is_debugger_attached`（行 227-228）
  - `mono_debug_lookup_source_location` 等（行 206）
  - 文件头注释（行 1-5）：「This header is only installed for use by the debugger」—— 说明该 SDK 发行版专为调试用途安装了 sdb 头
- **运行时证据**（`csharp_test/p7_verify.log:4-6`）：
  ```
  [Mono] P7: Enabling sdb debugger agent on 127.0.0.1:55556 (suspend=n)
  [Mono] Calling mono_jit_init_version (JIT mode)...
  [Mono] mono_jit_init_version succeeded, domain=0000026AC87C2520
  ```
  `mono_jit_parse_options("--debugger-agent=transport=dt_socket,server=y,suspend=n,address=127.0.0.1:55556")` 被 Mono **无报错接受**，随后 `mono_jit_init_version` 成功。若 `--enable-debug` / `--with-monodbg` 未在构建时启用，`--debugger-agent=` 选项会被拒绝或 agent 无法启动。

### 结论
**PASS**（间接证明）—— 桌面 Mono 静态库 `libmono-static-sgen.lib` 原生支持 sdb，无需重编。证据链：sdb API 头文件已安装 + 运行时 `--debugger-agent=` 选项被无错接受 + runtime init 成功。直接 `dumpbin /symbols` 验证因环境限制未执行，但运行时行为已构成强间接证明。

## 核查项 2：桌面 Mono 静态库（非 WASM）含 sdb 符号

### 核查方法
1. 用 Glob 列出 `mono/libs/` 下所有静态库，区分桌面 vs WASM
2. 核对 SCsub 中桌面构建路径与 WASM 构建路径分离
3. 用运行时日志确认 sdb agent 在桌面构建中实际启动

### 发现
- **桌面库**（`mono\libs\windows\x64\*.lib`）：3 个 `.lib` 文件，被 Windows editor 构建链接（SCsub:429-461）
- **WASM 库**（`mono\libs\web\wasm\*.a`）：11 个 `.a` 文件（`libmonosgen-2.0.a`、`libmonoruntimesgen.a`、`libmini.a`、`libmono-ee-interp.a` 等），完全独立的库集
- **SCsub 路径分离**：
  - Windows 桌面（SCsub:429）：`mono_root + "/libs/windows/x64"` → 链接 `libmono-static-sgen.lib`
  - WASM（SCsub:524, 568）：`mono_root + "/libs/web/wasm"` → 链接 `libmonosgen-2.0.a` 等
- **运行时证据**（`p7_verify.log:4`）：sdb agent 在 Windows editor 构建中启动成功（"P7: Enabling sdb debugger agent on 127.0.0.1:55556"）
- **WASM 端无 sdb 泄漏**（phase2 报告 §3.2 S 级）：`check_wasm_leak_v2.ps1` 确认 WASM 目标文件中无 `--debugger-agent=` / `GODOT_MONO_DEBUGGER_PORT` 等 TOOLS 字符串，符合 spec [REV-#08]

### 结论
**PASS** —— 桌面 `.lib`（非 WASM `.a`）含 sdb；WASM `.a` 不含 sdb（符合 spec §4.P7「仅桌面受益」定位）。两类库物理分离，构建路径独立，无交叉污染。

## 核查项 3：`mono_jit_parse_options` 在 `mono_jit_init_version` 之前 + IDE 附加/断点/单步

### 核查方法
1. 读取 `modules/mono/mono_host.cpp:265-300` 的 P7 实现块
2. 用 Grep 列出所有 `mono_jit_init_version` 调用行号，验证全部在 `mono_jit_parse_options`（行 297）之后
3. 核查 `csharp_test/p7_verify.log` 的运行时执行顺序
4. 核查 phase2 评审报告中 IDE 附加 / 断点命中 / 单步的验证记录

### 发现
- **P7 实现块**（`mono_host.cpp:265-300`）：
  - 条件编译：`#if defined(TOOLS_ENABLED) && !defined(WEB_ENABLED)`（行 265）—— 仅编辑器 + 桌面生效
  - 配置源：`ProjectSettings` 的 `dotnet/debugger/enabled`（默认 false）+ `dotnet/debugger/port`（默认 55555）（行 278-281）
  - 环境变量覆盖：`GODOT_MONO_DEBUGGER_PORT`（行 283-290）
  - 选项字符串：`--debugger-agent=transport=dt_socket,server=y,suspend=n,address=127.0.0.1:<port>`（行 292）
  - **`mono_jit_parse_options(1, opt_argv)` 在行 297**
- **`mono_jit_init_version` 全部调用点**（均在行 297 之后）：
  - 行 335：`mono_jit_init_version("GodotMonoHybridAOT", "v4.0.30319")`（Hybrid AOT 模式）
  - 行 386：`mono_jit_init_version("GodotMonoAOT", "v4.0.30319")`（AOT 模式）
  - 行 410：`mono_jit_init_version("GodotMonoInterp", "v4.0.30319")`（解释器模式）
  - 行 419：`mono_jit_init_version("GodotMono", "v4.0.30319")`（JIT 模式）
  - **顺序约束「必须在 mono_jit_init_version 之前」对所有 4 条代码路径均满足**
- **运行时执行顺序**（`p7_verify.log:4-6`）：
  ```
  [Mono] P7: Enabling sdb debugger agent on 127.0.0.1:55556 (suspend=n)   ← parse_options 已执行
  [Mono] Calling mono_jit_init_version (JIT mode)...                        ← 随后 init
  [Mono] mono_jit_init_version succeeded, domain=0000026AC87C2520          ← init 成功
  ```
- **IDE 附加 / 断点 / 单步验证**（phase2 报告 `docs/review_2026-07-25_phase2.md:36, 164-165, 174`）：
  - 端口监听：`Get-NetTCPConnection -LocalPort 55556 -State Listen` PASS
  - TCP 连接：`System.Net.Sockets.TcpClient` 连接 127.0.0.1:55556 成功
  - 引用验证脚本 `verify_p7_debugger.ps1` 全 PASS（注：该脚本在 v2 整理时已删除，结果见 phase2 报告）
- **缺口**：
  - spec §4.P7 要求的「IDE 附加、断点命中、单步执行正常」缺少提交的会话日志/截图证据，仅 phase2 报告文字声明端口/TCP 层通过

### 结论
**PARTIAL PASS** —— 选项调用顺序正确（行 297 < 行 335/386/410/419），运行时启动验证通过，端口监听 + TCP 连接 PASS。但 spec §4.P7 要求的「IDE 附加、断点命中、单步执行正常」缺少提交的日志证据，仅 phase2 报告文字声明。建议补一次 Rider/VS 实际 attach 会话并截图归档，以完整闭合 spec 验收项。
