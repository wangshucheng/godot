## 一、WASM 端 .pdb 可用性核查结果

### 1.1 实测产物（`bin/templates/web/`）
WASM 导出模板目录下仅含 `.js / .wasm / .html / .zip`，**未发现任何 `.pdb` 文件**。

### 1.2 构建脚本
- 项目使用 `build_web_template.ps1`（构建树）和 `godot-mono-wasm/tools/build_web_interpreter.ps1`（源码树）
- 脚本仅执行 `scons platform=web ...`，**无任何 .pdb 拷贝/嵌入逻辑**

### 1.3 BCL 嵌入逻辑（`modules/mono/SCsub`）
- `_select_bcl_dlls()`（SCsub:73-107）使用**白名单**策略，只选 `_BCL_WASM_REQUIRED_DLLS` + 环境变量 `BCL_WASM_EXTRA_DLLS` 中的 `.dll`；显式排除 `.so`，**全程未提及 `.pdb`**
- `_embed_bcl_assemblies()`（SCsub:110-171）通过 emcc `--embed-file file@mount` 逐文件嵌入；Facades 子目录过滤条件为 `f.endswith(".dll")`（SCsub:161-162），**.pdb 不会被嵌入**

### 1.4 项目程序集导出（[mono_export_plugin.cpp:13-66](file:///C:/Users/Administrator/AppData/Roaming/TRAE%20SOLO%20CN/ModularData/ai-agent/work-mode-projects/6a47fad25801ac16b9570799/godot4.7_mono/modules/mono/mono_export_plugin.cpp#L13-L66)）
`MonoExportPlugin::_export_begin` 仅向 PCK 注入两个文件：
1. `res://.mono/assemblies/<ProjectName>.dll`
2. `res://.mono/assemblies/GodotSharp.dll`

**.pdb 文件从不被打入 PCK**（既不打入桌面导出 PCK，也不打入 WASM 导出 PCK）。注释明确：Web 端 BCL 由 emcc `--embed-file` 嵌入 WASM MEMFS，项目 assembly 走 PCK —— 两条路径都不含 .pdb。

### 1.5 结论
**WASM 端 .pdb 完全不可用**：既不在 WASM 模板里，也不在导出 PCK 里，运行时无法获取。即便强行让 `MonoExportPlugin` 把 `.pdb` 加进 PCK，WASM 端 Mono 运行时也从未调用 `mono_debug_init` / `mono_debug_open_image_from_memory`（见 §二），无法消费 .pdb。

## 二、Mono 6.12 .pdb API 可用性

### 2.1 头文件位置
`mono/include/mono-2.0/mono/metadata/mono-debug.h`

### 2.2 关键 API（已核实存在于头文件）
| API | 行号 | 用途 |
|---|---|---|
| `MonoPPDBFile` 结构体 | 20 | Portable PDB 文件类型（Mono 6.x 原生 PPDB 支持） |
| `MonoDebugHandle.ppdb` 字段 | 80 | 每个 image 可挂一个 PPDB 句柄 |
| `MonoDebugSourceLocation` 结构体 | 107-111 | 含 `char *source_file; uint32_t row, column, il_offset;` |
| `mono_debug_init(MonoDebugFormat)` | 157 | 初始化调试子系统（必须最先调用） |
| `mono_debug_open_image_from_memory(MonoImage*, const mono_byte*, int)` | 158 | 从内存字节加载 .pdb（WASM 场景必需） |
| `mono_debug_lookup_method(MonoMethod*)` | 173 | 返回 `MonoDebugMethodInfo*` |
| `mono_debug_method_lookup_location(MonoDebugMethodInfo*, int)` | 200 | 按 IL offset 返回 `MonoDebugSourceLocation*` |
| `mono_debug_lookup_source_location(MonoMethod*, uint32_t, MonoDomain*)` | 207 | **核心 API**：直接反查源文件路径 |
| `mono_debug_free_source_location(MonoDebugSourceLocation*)` | 213 | 释放返回的结构体 |

### 2.3 当前调用情况（关键负面发现）
在 `modules/mono/` 全量 grep `mono_debug_init / mono_debug_open / mono_debug_enabled` —— **零匹配**。即：
- 运行时**从未调用 `mono_debug_init`**，调试子系统处于未初始化状态
- 即便 .pdb 文件存在于磁盘，Mono 也不会自动加载它（自动加载需先 init）
- `mono_debug_lookup_source_location` 在当前进程里**永远返回 NULL**

### 2.4 结论
**API 表面可用，但运行时未启用**。要在桌面端启用 .pdb 反查，必须先在 `mono_host.cpp` 初始化路径里调用 `mono_debug_init(MONO_DEBUG_FORMAT_MONO)`。Mono 6.12 在 `mono_assembly_open` 时若已 init，会自动加载 `.dll` 旁同名的 `.pdb`（Portable PDB），无需手动 `open_image_from_memory`。

## 四、实施方案建议（Conditional GO）

### 4.1 桌面端（GO — 完整 .pdb 反查）

**前置改动**（必须）：
1. 在 [mono_host.cpp](file:///C:/Users/Administrator/AppData/Roaming/TRAE%20SOLO%20CN/ModularData/ai-agent/work-mode-projects/6a47fad25801ac16b9570799/godot4.7_mono/modules/mono/mono_host.cpp) 的 Mono 初始化路径里，`mono_jit_init_version` 之后、首次 `mono_assembly_open` 之前，调用 `mono_debug_init(MONO_DEBUG_FORMAT_MONO)`
2. 验证 `scripts_assembly` 加载后 `.mono/assemblies/<ProjectName>.pdb` 被自动 attach
   - 兜底：若自动加载失败，用 `FileAccess::get_file_as_bytes` 读 .pdb 字节，调 `mono_debug_open_image_from_memory(image, bytes, size)`

**反查实现**（在 `refresh_global_classes` 里扩展）：
- 对每个 [GlobalClass] 类，取其任意方法的 `MonoMethod*`（建议取 `.ctor`，构造函数一定存在）
- 调 `mono_debug_lookup_method(method)` 拿 `MonoDebugMethodInfo*`
- 调 `mono_debug_method_lookup_location(minfo, 0)` 拿 `MonoDebugSourceLocation*`
- 读 `source_file` 字段，做相对 `res://` 的归一化
- `GlobalClassInfo` 新增 `String source_path` 字段，缓存改为 `HashMap<String(class_name), GlobalClassInfo>`

**`get_global_class_name` 改造**：
- 新增反向索引：`HashMap<String(source_path), String(class_name)>`（在 `refresh_global_classes` 里同步构建）
- 用 `p_path` 直接查反向索引，**彻底解除文件名==类名约束**
- 缓存 invalid 时仍回退文本扫描（保留现有兜底）

**关键文件改动清单**：
- `modules/mono/mono_host.cpp` — 加 `mono_debug_init` 调用
- `modules/mono/csharp_script.h:170-175` — `GlobalClassInfo` 加 `source_path` 字段，加反向索引
- `modules/mono/csharp_script.cpp:1635-1698`（refresh_global_classes）— 加 .pdb 反查 + 反向索引构建
- `modules/mono/csharp_script.cpp:343-374`（get_global_class_name）— 用反向索引替代 `get_file().get_basename()`

### 4.2 WASM 端（NO-GO — 维持文件名约定）

**理由**：
- .pdb 不在 WASM 模板、不在 PCK、不在 MEMFS（§一已证实）
- 即便强行嵌入，WASM Mono 解释器模式下 `mono_debug_*` 的代码路径未经验证
- 体积成本：portable .pdb 通常 50KB–500KB/assembly，对微信小游戏 WASM 包体不友好

**WASM 端策略**：
- `get_global_class_name` 在 WASM 编译期（`#ifdef WEB_ENABLED`）**直接走文件名约定分支**，不查 .pdb
- 即：WASM 端 `refresh_global_classes` 不调用 `mono_debug_*`，`get_global_class_name` 沿用 `p_path.get_file().get_basename()` 作为 cache key
- **副作用**：WASM 导出游戏若用户违反文件名==类名约定，类将无法被运行时识别 —— 需在编辑器端（桌面）做 lint/构建期校验，提前报错

### 4.3 编辑器 lint 建议（强烈推荐配套项）
桌面端启用 .pdb 反查后，编辑器在导出 WASM 前应扫描 `global_class_cache`，对每个 `[GlobalClass]` 类检查 `source_path.get_file().get_basename() == class_name`，不匹配则导出失败并提示用户重命名。这样可以在编辑期捕获 WASM 不支持的命名偏差，避免运行时静默丢失类。

## 五、GO / NO-GO 结论

**Conditional GO**：
- 桌面端编辑器：**GO**。Mono 6.12 .pdb API 齐全，.pdb 文件已由 `DebugType=portable` 自动生成，仅需启用 `mono_debug_init` + 扩展 `refresh_global_classes`
- WASM 端运行时：**NO-GO**。.pdb 完全不可用（模板/PCK/MEMFS 三处均无），维持文件名==类名约定，靠编辑器 lint 兜底

**风险点**：
1. `mono_debug_init` 调用后，Mono 行为会发生全局变化（异常栈会带源文件行号、JIT 略慢）—— 需验证对编辑器热重载性能无显著影响
2. `mono_debug_lookup_source_location` 对无方法的纯类型（如枚举/委托）可能返回 NULL —— 实现时需用 `.ctor` 而非任意方法
3. Portable PDB 的 `source_file` 是编译时记录的绝对路径或相对路径，需处理路径归一化（去项目根前缀，转 `res://`）
4. 反向索引在 assembly 重载时必须同步失效（`refresh_global_classes` 已 clear，安全）
